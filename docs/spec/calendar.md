# Teams' calendar — spec (TASK-0050)

Measured in Teams on the web as ost-test1 on 2026-11-17, inside OST's own
web profile on linuxlt (1852×988 viewport, 1x). Teams' calendar is Outlook
on the web's calendar hosted in an iframe
(`outlook.office.com/hosted/calendar/…`); its scheduling form and event
page for Teams meetings ("calv2") are Teams' own. The same app runs in
Teams desktop.

## Requests

| What | Request |
| --- | --- |
| Week data | Outlook's `outlookgatewayb2/graphql` and `service.svc?action=GetCalendarView`; OST reads Graph `/me/calendarView` with `Prefer: IdType="ImmutableId"` (the ids Outlook uses). |
| RSVP (card, event page, "RSVP with note") | `POST outlook.office.com/owa/service.svc?action=RespondToCalendarEvent&app=Calendar`, empty body; the JSON in the `x-owa-urlpostdata` header: `RespondToCalendarEventJsonRequest` with `EventId` (the occurrence, or the series), `Response` Accept/Decline/Tentative, `SendResponse` ("Email organizer"), `Notes` `<div>note</div>` (HTML), `Attendance` 0, `Mode` 0; headers `action`, `x-req-source: Calendar`, `prefer: IdType="ImmutableId", exchange.behavior="IncludeThirdPartyOnlineMeetingProviders"`.  Follow is `Response: "Tentative"` with `Attendance: 3` (Teams desktop bundle: AttendanceType None 0, InPerson 1, Online 2, Follow 3); Outlook then marks the event free and its subject "Following: ". The token is the hosted calendar's (app ceb96695-e468-48ba-ba21-35e2a242d396 through Teams' broker, scope outlook.office.com/.default); the service also needs a browser User-Agent, `x-owa-hosted-ux: true`, `x-owa-host-app: teams_desktop` and the JSON encoded as encodeURIComponent (a "+" for a space fails with TimeZoneException). |
| RSVP from Teams' own event page (calv2) | `PUT {mt}/v2.0/me/calendars/events/{iCalUId}/respond?eventType=Single|Occurrence|RecurringMaster&eventStartDateTime=…` `{responseType: Accept|TentativelyAccept|Decline, sendResponse, comment, attendance: None|Follow}` (Teams' calendar service bundle). OST uses it when the sign-in is device code (no broker). |
| Send update / Cancel on a channel meeting (organizer) | `PUT {mt}/v2.0/me/calendars/events/{objectId}?isOnlineMeeting=…` `{updatedCalendarEvent}`; `PUT {mt}/v2.0/me/calendars/events/{objectId}/cancel` `{cancellationMessage}` (objectId: the REST id). | Send on your own event (a Teams meeting too) | Teams' event page is Outlook's form for every event you organise, Teams meetings included (winpc, 2026-11-23; a Teams meeting's update was captured the same way, plus an `IsDefaultPreferences` extended property OST doesn't send): `POST outlook.office.com/owa/service.svc?action=UpdateCalendarEvent&app=Calendar` (from the hosted calendar's worker), `UpdateCalendarEventJsonRequest` with the header's `TimeZoneContext` (the mailbox's zone, e.g. "Pacific Standard Time") and a body of `EventId` (the immutable id), `ItemChange {Updates, ItemId}`, `EventScope` 0, `ShouldSendUpdateToAttendees` false, `TargetAudience` 0, `ClientSupportsIrm` true. `Updates` holds only what changed, as `SetItemField`s on a `CalendarItem` (`Subject`, `Start`/`End`, `Location`, `Body`, `LegacyFreeBusyStatus` as `FreeBusyType`…); when the attendees changed, the whole `RequiredAttendees`/`OptionalAttendees` lists (`{Mailbox: {Name, EmailAddress, RoutingType: "SMTP"}}`) and `AddedRequiredAttendees`, `AddedOptionalAttendees`, `AddedResources`, `RemovedRequiredAttendees`, `RemovedOptionalAttendees`, `RemovedResources`. Exchange sends the attendees the update (new attendees an invitation). When only the attendees changed (title, times, place and repeat as they were, attendees before and after), Outlook asks first: "Send update" / "You've made changes to the attendee list. Do you want to send updates to only added/removed attendees or all of them?" with "Only added/removed attendees" (primary, `TargetAudience` 2) and "All attendees" (`TargetAudience` 1). |
| Change a series' repeat | On an occurrence the page says "You're editing one event in the series." with "Edit series" and "Edit this and all following events"; Edit series shows "Occurs every Tuesday from 3:00 PM to 3:30 PM effective Tue 11/24/2026 until Tue 12/15/2026". (Save, Cancel), then sends `UpdateCalendarEvent` on the series master's id with `SetItemField` `Recurrence`: `{__type: "RecurrenceType:#Exchange", RecurrencePattern: {__type: "WeeklyRecurrence:#Exchange", DaysOfWeek: "Tuesday Thursday", FirstDayOfWeek: "Sunday", Interval: 1}, RecurrenceRange: {__type: "EndDateRecurrence:#Exchange", EndDate: "2026-12-15", StartDate: "2026-11-24"}}` (each also with a `__typename`; others: `DailyRecurrence {Interval}`, `AbsoluteMonthlyRecurrence {DayOfMonth, Interval}`, `AbsoluteYearlyRecurrence {DayOfMonth, Month}`, `NoEndRecurrence {StartDate}`), `EventScope` 0. |
| This and all following events | The card's Edit on your series' event is a split button: "This event", "This and all following events", "All events in the series" (Cancel has a ▾ with the same three: see Cancel your event). This and all following opens the page with "You're editing this and all following events in the series."; the attendees can't change there ("You can only change attendees by editing the series." with "Open series"), the time row reads "Occurs every Monday from 9:00 PM to 9:30 PM effective Mon 12/7/2026 until Mon 5/17/2027" (the series' repeat from this event's date) and opens the same Start date / times / Repeat every editor. Send asks nothing and sends `UpdateCalendarEvent` on the occurrence's id with `EventScope` 2 and only what changed (a title: `Subject`; a new time and repeat: `Start`/`End` as wall times with `StartTimeZoneId`/`EndTimeZoneId`, and `Recurrence` whose `RecurrenceRange.StartDate` is the occurrence's date, e.g. `WeeklyRecurrence` "Monday Wednesday" from 2026-12-07 until 2027-05-17); Exchange ends the series before that event and makes a new series from it (Teams desktop, winpc, 2026-11-23). |
| Does not repeat on a series | Teams' event page has no way to stop a series repeating: the series' editor offers Repeat every 1–N day/week/month/year, the weekdays and Until with "Remove end date", and the Event/Series switch is only on a new event (winpc, 2026-11-23). A fresh load of `hosted/calendar/item/<id>` goes back to the calendar view, so OST loads the calendar and routes it there (pushState), as Teams' own navigation does; when Outlook leaves the event page (Send, Cancel, Close) the layer closes. Outlook's form draws its own 48 px title bar ("<subject> - Meeting - Calendar", Open in new window, Close). Without a browser sign-in, Propose new time falls back to OST's own propose dialog.
- **Event form pop-out.** Outlook's form, hosted in Teams desktop (host TeamsModern, desktop), pops itself out with `stageView.open` (flight cal-forms-stageView-popout-enabled); the bar's Open in new window does the same. OST opens the page in a window of its own, which closes on `stageView.self.close`.
- **Copilot prompts.** A suggestion or card prompt goes into the pane the way Teams' calendar hands it over: once the pane is ready the host sends `updatePromptInputData` with `{promptText, correlationId, promptTimestamp, isDraft, focusOnLoadTarget: "Compose"}`. Outlook's calendar strings give the prompt for each chip, e.g. "Schedule 1 hour of focus time" sends "Schedule 1 hour of focus time for me in the next week". "Find my next one-on-one with" stays a draft ("When is my next one-on-one with /").
- **Scheduling time zone.** When the middle tier gives no name for your zone (OST Test 3's mailbox has none), the meeting goes in UTC with its times in UTC, so it lands at the time you picked.
- **Event page**: Teams' event page for a meeting is Outlook's reading form, `hosted/calendar/item/<id>`: the answer split button ("Tentatively accepted ▾"), Delete, Forward ▾, Duplicate, Show as ▾, reminder, category and privacy menus, Print, Save as .ics, Join and Chat; "Prepare for your meeting" (Show insights; Talking points, Meeting outcomes, Prep me for this); then the title, attendees with Tracking, the time with Scheduler, "Add a room with Copilot", the Teams meeting toggle and the description.
- **Live meetings dialog**: each card's people come from watching the meeting's call without joining (`subscribedCallChangedEvent` with requireJoinWithoutModality): at most 3 avatars, then +N (participants-live-roster-list). From Teams' Griffel CSS (griffel-37c74cd32cb2b4d1.css; not measured live, as winpc's Teams got no MeetingStart in the test): each avatar's margin is 0 -1rem 0 0 (html font-size 10px, so a 10 px overlap), the list pads 1rem on its right, and +N is an avatar of the same size (isHiddenParticipantsCounter). Checked live in OST with two fresh meetings: E with OST Test 2 and three admitted guests showed three avatars and +1, F showed O3.
